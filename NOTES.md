### ANTLR + Groovy (nix/java/antlr.nix, nix/java/groovy.nix) — for Gradle
* ANTLR 2.7.7 → StringTemplate 3 → ANTLR 3.1 → 3.3 → ST 4.0.6 → ANTLR 3.5.2
  (twice) → ST 4.0.8 → ANTLR 4.1 → tunnelvisionlabs ANTLR 4.7.4 (twice), as
  in Guix.
  * icu4j is only used at build time to generate ANTLR 4's Unicode tables.
    Its data (`icudata.jar`) is built from source in `nix/java/icu`: the
    ICU 70.1 git tree with all prebuilt data (`*.jar`, `data/in/*.icu`/`*.nrm`,
    the generated `*_data.h` headers) stripped at fetch time; gennorm2,
    genprops and genuca are compiled from the source subsets listed in ICU's
    Bazel BUILD files (`bazel-srcs.py`, no Bazel needed) and regenerate that
    data from `data/unidata/*.txt`, as ICU's `generate.sh` does; then ICU4C
    builds its data from text (`--include_uni_core_data`) and
    `make icu4j-data` packs the jar.  `i18n/collationfcd.cpp` (generated by
    genuca, linked into genuca) is regenerated and checked to be unchanged.
    The result is byte-identical to upstream's prebuilt jar (all 3826
    entries).
* Groovy 3.0.5: javac-only bootstrap → joint compile of the whole core with
  `FileSystemCompiler` → subprojects (test, xml, templates, json, nio,
  datetime, dateutil, sql, astbuilder, docgenerator, groovydoc, ant).
* JavaCC (for javaparser, used by groovydoc) is written in JavaCC.  Guix
  keeps the bundled `bootstrap/javacc.jar`; here the seed is instead the
  Maven *sources* jar of 7.0.4 (generated parsers as plain Java), which is
  compiled and then used to rebuild JavaCC from git, regenerating the parsers.
* qdox 1.12.1 from its Maven sources jar (as Guix).  Built with JDK 11 (needs ≥ 9) — currently nixpkgs'
  temurin-seeded openjdk11, to be replaced by the chain's.
* javaslang 2.0.6 (Kotlin ≥ 1.1.3): its `src-gen` (generated by a Scala
  tool) is committed upstream and used as is.

## Status: Kotlin 1.2.31 (Ant era complete)

Built with Ant from source: 1.1.3-dev-1317 .. 1.1.4, 1.1.51, 1.1.60, 1.2.0,
1.2.10, 1.2.21, 1.2.31 (`nix build .#kotlin."1.2.31"`).  Per-version notes:
* 1.1.3+: `build.xml` delegates the runtime to Gradle, so the Ant runtime
  targets of 1.1.2 are spliced back (`patches/own/runtime-targets-*.xml`).
  1.2.x versions: kotlin-test needs `annotations-common` (expect decls) and
  `-Xmulti-platform` (1.2.0); `core/descriptor.loader.java` became
  `core/descriptors.jvm` (1.2.21); builtins also include
  `libraries/stdlib/jvm/runtime` (1.2.31).
* 1.2.10: compiler needs `-jvm-target 1.8` (Java-8 static interface calls).
* 1.2.31 needs IntelliJ SDK 181 (JavaModuleSystem, JvmElementProvider);
  `patches/own/sdk-181.patch` is sdk-173's port, plus lz4-java replaced by
  Snappy in `CompressionUtil`.  `compiler.xml` moved to `compiler/cli/src`.
* JDK 12+: glibc >= 2.42 declares `uabs()` (renamed in hotspot), 14+ needs a
  stub `<sys/sysctl.h>` (jpackage).

## Status: Kotlin 1.2.40 .. 1.2.71 (restored build.xml)

* 1.2.40+: `build.xml` is gone upstream; 1.2.31's is reused (plus new module
  dirs).  1.2.50+: "fresh stdlib" (the new stdlib compiled by the previous
  compiler) as `bootstrap.runtime`, `-Xread-deserialized-contracts
  -Xeffect-system`.
* 1.2.60: stdlib needs `-Xuse-experimental=kotlin.Experimental`; 1.2.70 also
  `kotlin.ExperimentalMultiplatform`, IntelliJ SDK 182, `-Xnew-inference`
  (sources are written for it) with callable references to vararg
  constructors / inline functions rewritten as lambdas (codegen crashes),
  and `kotlin-annotations-jvm` compiled into `lib/`.
* IntelliJ SDK 182/183/191/192/193 (`patches/own/sdk-NNN.patch`): JDOM 2
  fork, ASM 7, lz4 replaced by a small `lz4-compat`, imgscalr, streamex, JNA
  5, commons-compress (+ xz, brotli, zstd stub); SVG/batik, mac UI and form
  instrumentation removed.
* JDK chain reaches 21 (19+: jmod `--date` needs SOURCE_DATE_EPOCH >= 1980).

### 1.3.0 (from 1.2.71)
Upstream built 1.3.0 from 1.3 pre-releases only.  1.2.71 has the 1.3
language features as unstable ones, but its release-coroutines codegen
targets `kotlin.SuccessOrFailure` (renamed to `Result` in 1.3-RC).  So the
fresh stdlib (only compiled against) has `Result` renamed back, and the
compiler built by 1.2.71 must not use coroutines itself: two `sequence {}`
blocks are rewritten, `runBlocking` replaced by a latch.  The stdlib's
1.3-only binaries are "pre-release" for 1.2.71 →
`-Xskip-metadata-version-check`.

## Plan beyond Kotlin 1.1.2-5

* Kotlin's Ant build.xml survives until 1.2.31 (gone in 1.2.40), but from
  1.1.60 on the runtime/stdlib are built by Gradle (`gradle-runtime` target).
  → continue with Ant through 1.1.3/1.1.4/1.1.51 (TarCV's leftover patches),
  then replace the `gradle-runtime` target by a direct kotlinc build of the
  stdlib, up to ~1.2.31.
* After that: write per-version Nix builds that compile the compiler modules
  directly with the previous kotlinc + javac (no Gradle), stepping through
  `build-*-dev-*` tags.  Needs newer IntelliJ SDK modules (173, 181, 183, …),
  which themselves contain Kotlin code from some point on, so the IntelliJ and
  Kotlin chains have to be interleaved.
* Gradle: compile a recent Gradle's subprojects directly (javac/groovyc/
  kotlinc) instead of bootstrapping Gradle-with-Gradle; needs Groovy (Guix
  has a from-source Groovy recipe) and Kotlin ~2.x with scripting/embeddable
  artifacts.

## Kotlin 2.1.0 → 2.4.0 (done)

Chain: 2.0.0 (K1 only) → 2.1.0 (FIR, built by 2.0.0) → 2.1.20 (bridge: first with named
context parameters) → 2.2.0 → 2.3.0 → 2.4.0 (`nix build .#kotlin."2.4.0"`).
Things worth knowing:
* FIR needs `ANT_OPTS=-Xmx14g`; the stdlib/builtins/reflect are compiled from source by K2.
* 2.3 split/merged many modules (psi, cli-common, ...) and 2.4 moved more (core/names,
  core/language.*, cli-jvm, cli-metadata): `relocate-modules*` steps move files back to
  where the inherited patch steps expect them; new module dirs are added in the dir lists.
* The 2.3.0 compiler ignores `-Xopt-in` for some args (use `-opt-in`), and cannot compile
  explicit backing fields on overrides / `return` in expression bodies: patched in 2.4 sources.
* 2.4's JS parser is ANTLR-generated: regenerated with the tunnelvisionlabs ANTLR 4.7.4 chain
  (nix/java/antlr.nix) instead of the committed 4.13.2 output.
* CRI (kotlinx.serialization plugin) is dropped; Ant tasks are gone since 2.3 (kotlin-ant.jar is
  handed down from the bootstrap).
Next: Gradle 9.8.0 (~10.5k Java, 770 Kotlin, 110 Groovy main sources in ~190 modules; see the
8.14.3 survey above) compiled module by module with javac/groovyc/kotlinc.

## Gradle 9.8.0 (from source, 2026-10-24)

`nix build .#gradleDist` → a working Gradle distribution (lib/, lib/plugins, lib/agents, bin/gradle).
Smoke test: `JAVA_HOME=$(nix build --no-link --print-out-paths .#jdks.openjdk21) result/bin/gradle --offline --no-daemon build`
(Groovy and Kotlin DSL builds, `java`/`application` plugins verified).

* Third party libraries: `nix/gradle/libs.nix`; Groovy 4.0.33: `groovy.nix`.
* Modules: every Gradle module is compiled directly with javac/kotlinc (`modules.nix`); the module graph is
  extracted from the build scripts by `tools/gradle-modules` into `modules.json` (regenerate against a Gradle checkout).
* Kotlin pieces (`kotlin-plugins.nix`): compiler plugins, scripting libs, kotlinx.serialization, build-tools-api/impl,
  built from the Kotlin 2.4.0 sources; `kotlin-embeddable.nix` + `Relocate.java` relocate them like Kotlin's embeddable
  (jarjar cannot read modern classes). The bootstrapped compiler's bundled ASM cannot read sealed classes, so a modern
  ASM relocated to org.jetbrains.org.objectweb (with a shim) goes first on the classpath (`kotlinAsm`).
* Distribution (`dist.nix`): module registry `*.properties`, gradle-runtime-api-info (`gen-api-info.py`,
  `InstrumentationMetadata.java`), build receipt, jar manifests, a public-api jar (full classes instead of ABI stubs).
  `kotlin-extensions.nix` generates the Kotlin DSL extensions of the Gradle API with the code generators of
  kotlin-dsl-shared-runtime (`GenerateExtensions.java`).
* Not done: resources-s3/gcs and build-init (AWS/GCS/maven-core libs), api-relocated.txt (empty), tests of the
  test-kit/native/plugin-development plugins, Scala compilation (no Scala compiler: the Zinc worker is stubbed, throws).

### Gradle 8.14.3 (2026-10-24)

`nix build .#gradle."8.14.3".dist` (and `.#gradle."9.8.0".dist` = `.#gradleDist`): a working 8.14.3
(Groovy-DSL and Kotlin-DSL `java`/`application` builds verified, offline, `--no-daemon`).
`gradleFor` in `nix/default.nix` instantiates modules + dist + generated Kotlin extensions for a Gradle version.
What differs from 9.8:
* module graph `modules-8.14.3.json` (`tools/gradle-modules`; `optionalProjects`, java-api-extractor, futureKotlin coords);
* Groovy 3.0.24 (`groovy3.nix`: antlr2 grammars + the tunnelvisionlabs ANTLR 4 for the Parrot grammar; official ANTLR
  4.9-4.13 reject its duplicate alt labels); Gradle 8 breaks at runtime on Groovy 4;
* Kotlin 2.1.0 compiler stack (`kotlinPlugins21`, `kotlinRelocated21`), because 8's Kotlin DSL uses compiler APIs that
  2.4 removed; kotlinx.serialization 1.6.2 and kotlinx-metadata-jvm 0.5.0 (from the Kotlin 1.7.0 sources);
* libs: slf4j 1.7.36 (`slf4jLegacy`), jansi 1.18 (Java only, no JNI), commons-lang 2.6, jsoup;
* module registry: each jar carries `<module>-classpath.properties` (`registryStyle = "embedded"`) instead of 9.x's sidecar files;
* small source patches in `default.nix` (`patches`: core, kotlin-dsl, instrumentation processor), `scala` is built partial like the Zinc worker.
Not done: AWS/GCS/maven modules, JNI libraries (jansi, native-platform), Scala compilation.

## Scala chain (nix/scala, scala/stages) — 2026-10-24, in progress

Goal: a current Scala without any Scala binary.  No from-source Pizza compiler exists, so the chain starts at the
last scala/scala commit with a complete Java ("scalacboot") compiler, 3b4e70e1bd (2004-02-19), and goes commit by
commit (`scala/proto/chain.txt`) through Scala 1.x, the first Scala 2 compiler (nsc, 2005-12) and 2.0.0 (s14) on.
`nix build .#scala.stages.<name>`, `.#scala."2.0.0"`, `.#scala.latest`; every stage's compiler must compile and run
`scala/stages/Hello*.scala` (installCheck).
* Pizza (algebraic `case` classes, pattern `switch`, …) → Java: `tools/pizza2java.py`, then javac; PiCo classfile
  conventions (JacoMeta/JacoInterface attributes, case fields) by `tools/pico-classfiles.py`.
* FJBG and the MSIL reader API from the 2009 sources (src/fjbg 0f10ffedc8, src/msil 4304b15730); the MSIL backend
  is stubbed in every stage (msil.jar was a binary until 2009).  jline 1.0 from source for the REPL (2007-07+).
* Old classfile readers are patched for Java 8 class files; they see the JDK through period-accurate API views
  (`tools/jdk-api-view.py`: Java 1.4 without Java 5 attributes, Java 1.5 with generic signatures; hidden supertypes
  flattened, signatures rewritten with substituted type arguments).
* Flag days: locker falls back to the previous library for classes the reference compiler needs, compiler-first
  lockers (new compiler by the old one against the old library), `bridge` stages (an old commit plus a few files of
  the next) standing in for unpublished intermediate reference compilers (b42: Java generics, 2007-12).
* JDKs: the chain's openjdk8 runs the compilers, openjdk21 (`--release 8`) compiles the Java parts.

Workflow: new stages are found with the prototype in /tmp/sc (`scala/proto`: climb/bisect/auto/diag, using the
same `scala/stages` scripts via symlinks in /tmp/sc/work and the /tmp/sc defaults of `env.sh`), recorded in
`scala/proto/chain.txt`; `tools/scala-chain` regenerates `nix/scala/chain.nix` (revisions + source hashes).
